# Paperworld — Human-first village audit (2026-11-18)

## Product rule
**The owner talks to Matt, not to infrastructure.** Development and status are internal implementation concerns. Directors can answer naturally, Workers execute only when authorized, and verified progress is projected in simple, accurate language. No display-only UI grants new capabilities.

## Source-level audit and treatment
| Area | What the owner previously saw | V2 treatment |
| --- | --- | --- |
| Village canvas / `index.html` | Paths editor, building editor, depth test and walkability overlay next to everyday controls | Hidden from normal view; explicit `?maintenance=1` recovers existing visual-only maintenance functions |
| World drawer | Map calibration tools, technical asset status, English setup/debug copy | Hidden maintenance panels, concise Greek labels |
| Matt Messenger / `js/world-dialogue.js` | Copilot infrastructure descriptions, route/report progress, MCP debugging controls and memory-import administration | Natural presence, conversational progress and optional read-only owner team status; diagnostics and imports remain maintenance-only |

| Project Work / `js/cloud-ui.js` | Legacy manual draft/pilot/simulation launchers mixed with actual work | Replaced by real owner-scoped mission progress; separate optional notes and legacy technical area |
| Mission read API | Historic mission status only; completed evidence unavailable to ordinary view | Owner/thread-scoped verified report made available to the activity projection only when completed |
| Matt reply generation | Director/team metadata and PR/endpoint phrases in ordinary answers | Short direct conversation instructions and truthful natural assignment replies |
| Human-first decisions | Real consent-sensitive review and approval surfaces | **Preserved**. Avoid hiding a required informed decision or silently authorizing an external effect |

## General orchestration boundary
One shared server controller and durable five-step Task Engine remain the authority for supported code work. The present UI is a **projection**, not another worker, scheduler or hidden executor. Luna and Joey have the currently verified Copilot coding path; Crow and Dave remain distinct capabilities with different scopes. Never claim that every Director has the same worker or connector access.

## Truthfulness and consent
- A draft is not underway; a queued item is not completed; an unverified completion is not represented as a proven result.
- Only a verified, owner-scoped coding result with an allowlisted project GitHub PR may open a result link, and even that is *prepared*, never automatically deployed.
- No background model calls from opening the village or activity view.
- Preserve all authorizations, budget caps, private wellbeing isolation and human approval for substantial external changes.
- Tech maintenance mode only changes presentation, not backend privileges.
