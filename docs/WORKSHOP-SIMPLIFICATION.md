# PAPERWORLD — one Developer per project, Chief for oversight

The Listening Mirror Workshop is the user's point of contact for Listening Mirror issues. The Chief of Staff oversees projects, not duplicate developer controls.

## Simplification
- One conversational Developer panel in the Listening Mirror Workshop.
- Exactly one canonical active TicketSwap mission, reused from existing cloud records.
- Older draft and cancelled mission records are preserved but hidden inside a collapsed archive.
- Cloud task details are collapsed by default.
- The confusing case-sensitive approval-text prompt is replaced by a clear, explicit human confirmation. The server still requires the fixed credit authorization and owner-scoped mission.
- The Developer offers Check progress, View report, and the explicitly confirmed AI investigation on a ready mission.
- The Chief displays a cross-project task summary rather than a second mission management console.
- No automatic AI usage, push, merge, deployment, or purchase.

## Honest boundary
This is a streamlined rule-based conversation for TicketSwap and a task recorder for other issues, NOT yet a fully general agent capable of diagnosing any arbitrary bug. A user-requested AI run can only analyze a temporary checkout and return an inspectable report; a separate approval would still be needed to publish changes.

## Acceptance
1. Open Listening Mirror Workshop: the Developer and message input should be visible.
2. Describe a TicketSwap problem: the existing ready mission should appear once.
3. Old/cancelled missions should no longer clutter the visible panel.
4. AI investigation must display a clear confirmation and do nothing on Cancel.
5. Chief of Staff should only summarize projects and tasks.

No existing Supabase mission records were deleted.
